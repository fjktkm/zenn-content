## 1. はじめに

TrueType Collection（TTC）は，複数のフォントを一つのファイルに格納するためのファイル形式です．主には同一のフォントファミリーにおいて Regular や Bold などの異なる太さのフォントをまとめるために使われます．フォント間で共通するテーブルを共有できるため，複数のフォントをまとめることでファイルサイズを削減できるという利点があります．

ところで，Google Fonts には数千個のフォントがあります．

だったら，**Google Fonts 全部入りの TTC** も作れるのではないか？

というわけで，この記事では実際に Google Fonts 全部入りの TTC を作ってみた件について紹介します．実際のところ，異なるフォントファミリーでは共通するテーブルはほとんど存在しないため，実用上のメリットは一切ありません．夏の自由研究としてお楽しみいただければ幸いです．

本検証で使用したコードは以下のリポジトリで公開しています．

https://github.com/fjktkm/google-fonts.ttc

## 2. 方法

### 2.1. 対象のフォント

Google Fonts のフォントは GitHub のリポジトリで管理されています．各フォントは `apache`，`ofl`，`ufl` といったライセンスごとのディレクトリの下に格納されています．

https://github.com/google/fonts

本検証の対象となるフォントは **2,048 ファミリー，3,793 ファイル** でした．ライセンス別の内訳は次のとおりです．

| ライセンス            | ファイル数 |
| --------------------- | ---------: |
| SIL Open Font License |      3,715 |
| Apache License 2.0    |         61 |
| Ubuntu Font Licence   |         17 |

### 2.2. 素朴な実装

フォントの操作には Python の `fontTools` ライブラリを使うのが一般的です．今回の検証でも，まずは素朴に `fontTools` を試してみることにしました．中心となる処理だけを抜き出すと，次のようになります．

```python
from fontTools.ttLib import TTCollection, TTFont

collection = TTCollection()
collection.fonts = [
    TTFont(path, lazy=True, recalcTimestamp=False) for path in font_paths
]
collection.save("output/google-fonts.ttc", shareTables=True)
```

`TTCollection` にすべての `TTFont` を渡して保存するだけなので，生成そのものは驚くほど簡単です．`shareTables=True` にすると，同じ内容のテーブルがコレクション内で共有されます．

## 3. 問題点

素朴な方法で生成した TTC を Windows のフォントビューアーで開こうとしましたが，正常に開くことができませんでした．そこで，対象とするフォントを減らしながら原因を調べました．

### 3.1. Gidugu-Regular.ttf

フォント数を減らした TTC は正常に開くことができました．対象を変えながら検証したところ，`Gidugu-Regular.ttf` が含まれている場合に開けなくなることがわかりました．

https://fonts.google.com/specimen/Gidugu

調べてみると，`Gidugu-Regular.ttf` が Windows で有効なフォントとして認識されず，インストールできない問題が Google Fonts の Issue に報告されていました．

https://github.com/google/fonts/issues/9982

TTC に `Gidugu-Regular.ttf` を含めると Windows で開けなくなったことと合わせて考えると，おそらく Windows では一つでも無効なフォントを含むと TTC 全体が無効なものとして扱われるようです．

### 3.2. 2 GiB の壁

`Gidugu-Regular.ttf` の Name ID 3 を補完し，あらためて Google Fonts 全体を対象に TTC を生成しました．しかし，それでもフォントビューアーで開くことはできませんでした．フォント数を減らした TTC は開けることから，今度はファイルサイズに原因があると考えました．

OpenType の TTC では各フォントへのオフセットが符号なし 32 bit 整数で表現されるため，形式上は 4 GiB 付近まで表現できます．一方，Windows GDI の `AddFontResourceExW` を使い，TTC の末尾にデータを足しながら境界を調べたところ，次の結果になりました．

| TTC のサイズ       | 結果 |
| ------------------ | ---- |
| 2,147,483,647 byte | 成功 |
| 2,147,483,648 byte | 失敗 |

境界はちょうど $2^{31}$ byte，**2 GiB** でした．これは OpenType 形式そのものの上限よりも小さい値です．したがって，Windows GDI の `AddFontResourceExW` には，TTC のサイズに独自の制約があると考えられます．

https://learn.microsoft.com/ja-jp/windows/win32/api/wingdi/nf-wingdi-addfontresourceexw

素朴な方法で生成した TTC は約 2.2 GiB で，この上限を超えてしまっていました．Windows で Google Fonts 全体入り TTC をインストールできるようにするには，どうにかしてファイルサイズを 2 GiB 未満に収める必要があったというわけです．

## 4. 解決策

### 4.1. Name ID 3 を補完する

`Gidugu-Regular.ttf` が Windows で認識されない原因を調べたところ，`name` テーブルに Windows 向けの **Name ID 3（Unique font identifier）** レコードがないことがわかりました．

そこで，Name ID 3 が存在しない場合に限り，既存のバージョン，ベンダー ID，PostScript 名から一般的な形式の識別子を組み立て，TTC の生成時に追加することにしました．

この変更はメモリ上のフォントに対して行い，Google Fonts から取得した元ファイル自体は変更していません．

### 4.2. HarfBuzz Subset で縮める

Windows で扱える 2 GiB 未満に収めるため，すべてのフォントを TTC に格納する前に HarfBuzz を使ってファイルを最適化することにしました．

https://github.com/harfbuzz/uharfbuzz

HarfBuzz Subset は，Subset という名前の通り本来は使用しない文字やグリフを取り除くための機能ですが，本検証では文字の削減は行いません．文字を削ってしまうと「Google Fonts 全部入り」ではなくなってしまうからです．

代わりに，TrueType のヒンティング情報などの比較的優先度の低い情報を削除することで，ファイルサイズを縮めることにしました．これにより，「Google Fonts 全部入り」のまま Windows の 2 GiB 制限を下回る **約 1.93 GiB** の TTC を実現することができました．

## 5. 動作確認

### 5.1. フォントビューアーで開く

完成した TTC を Windows のフォントビューアーで開いてみました．ウィンドウが表示されて操作可能になるまでの時間を 3 回計測したところ，5.01 秒，4.95 秒，4.93 秒で，平均は 4.96 秒でした．約 1.93 GiB のフォントファイルが 5 秒ほどで開けたのは意外な結果でした．

![](/images/95ec94e1c2ab38/windows-font-viewer.png)
_Windows のフォントビューアーで開いた様子_

最初に表示されたのは `Aclonica` です．右上の「次へ」を押すと，TTC に収録されたフォントを順番に表示できます．ここまでは通常の TTC と変わりません．

面白いのはウィンドウのタイトルです．フォントビューアーは TTC に収録されたフォント名を `&` で連結してタイトルに設定するようで，3,793 個のフォント名を並べたとんでもなく長いタイトルができあがりました．画面上では当然収まりきらず，途中？のごく一部だけが表示されています．

### 5.2. インストールする

次に，フォントビューアーから TTC を実際にインストールしました．約 1.93 GiB のファイルですが，コピーと登録は約 5 秒で完了しました．

インストール前に Windows の設定アプリで確認すると，使用可能なフォントは 334 個でした．

![](/images/95ec94e1c2ab38/fonts-before-install.png)
_TTC をインストールする前のフォント一覧_

インストール後は 2,464 個まで増えました．一つの TTC ファイルをインストールしただけで，フォント一覧に 2,130 個も追加されたことになります．Google Fonts のファミリー数である 2,048 とは微妙に一致しませんが，これは Google Fonts のディレクトリと Windows のフォント一覧でグループ化の単位が異なるためだと考えられます．

![](/images/95ec94e1c2ab38/fonts-after-install.png)
_TTC をインストールした後のフォント一覧_

一覧から `Aclonica` を開いてメタデータを確認すると，フォントファイルとして `google-fonts.ttc` が表示されました．ちゃんと検証で作成した TTC からフォントが読み込まれていることがわかります．

![](/images/95ec94e1c2ab38/font-details-aclonica.png)
_Aclonica のフォントファイルとして google-fonts.ttc が表示される_

### 5.3. アンインストールする

また，この画面から `Aclonica` 一つだけをアンインストールしようとすると，「フォント コレクション全体」を削除するか確認されました．TTC に収録されたフォントは個別にアンインストールできず，一つを削除しようとすると 3,793 個すべてがまとめてアンインストールされるようです．

![](/images/95ec94e1c2ab38/uninstall-font-collection-dialog.png)
_フォントコレクション全体の削除を確認するダイアログ_

## 6. 考察

### 6.1. サイズの制約

今回作成した Google Fonts 全部入りフォントファイルは，少なくとも Windows 上では限界に近いところで成立しています．完成した TTC ファイルは約 1.93 GiB で，Windows の 2 GiB 制限まで約 68 MiB しか残っていません．現時点では HarfBuzz Subset による最適化で制限を下回りましたが，今後 Google Fonts に新しいフォントが追加されれば，いずれは 2 GiB に収まらなくなるでしょう．したがって，自分がこの検証に取り組んだのはかなり幸運なタイミングだったように思います．

### 6.2. ライセンス

今回生成した TTC ファイルについては，配布したい気持ちはやまやまだったのですが残念ながら断念することになりました．というのも，各フォントのライセンスが求める再配布条件を満たすことが難しかったからです．

処理の過程ではヒンティングの削除やテーブルの書き換えを行っており，元のフォントに変更を加えています．そのため，変更後のフォントを再配布するには，それぞれのライセンスに応じた対応が必要です．主な問題は次のとおりです．

- SIL Open Font License の対象には Reserved Font Name を宣言するファミリーがあり，変更版で元の名称を使うには条件があります．対象には少なくとも 555 ファミリーが該当します．
- Apache License 2.0 のフォントを再配布するには，ライセンスや通知を同梱し，変更したファイルにはその旨を明示する必要があります．現在のビルドでは，そのための付属資料を生成していません．
- Ubuntu Font Licence の対象となる 5 ファミリーは，変換・最適化した生成物を Modified Version として扱う必要がありますが，派生物を区別する名称は付けていません．

これらの問題に適切に対応すれば再配布できる可能性はあります．しかし，名称の変更を行ってしまうと当初の「Google Fonts をそのまま全部一つにまとめる」というコンセプトからは少し離れてしまいます．そういうわけで，今回は生成物の配布は見送ることにしました．

## 7. おわりに

Google Fonts に収録された 3,793 個のフォントを，一つの TTC ファイルにまとめることができました．約 1.93 GiB という巨大なファイルになりましたが，Windows でも通常のフォントコレクションとして開き，インストールして利用できます．

最初は「TTC なら全部まとめられるのでは？」という単純な思いつきでしたが，実際に試してみると，個々のフォントのメタデータの問題や Windows の 2 GiB 制限など，単にフォントを束ねるだけでは済まない問題にぶつかりました．一方で，3,793 個ものフォントを一つのファイルに詰め込んでも，TTC として普通に扱えること自体はなかなか面白い結果だったと思います．

Google Fonts は今後も増えていくため，この「全部入り」が一つのファイルとして成立する期間はそう長くないかもしれません．少なくとも今回の検証では，2 GiB の壁まで残り約 68 MiB．世界最大かどうかはさておき，かなり限界まで詰め込んだフォントファイルを作ることができました．
